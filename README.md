# Sprint_7

В данном проекте реализован набор тестов для API сервиса Яндекс Самокат.
Тесты написаны на **Python** c применением **Pytest** и **Requests**.

- clients/ - описание API клиентов для вызова запросов
- tests/ - сами тестовые методы
- utils/ - вспомогательные методы для генерации данных
- conftest.py - фикстуры для создания методов
- endpoints.py - URL ресурсы для API методов
- status_codes.py - константы с кодами ответа и сообщениями

### Покрытие кейсы:

1. **Проверка API метода "Создание курьера" (test_create_courier.py):**  
   test_create_courier_success - успешное создание курьера со всеми обязательными полями;  
   test_create_courier_duplicate_shows_error - проверка ошибки при создании дубликата курьера;  
   test_create_courier_empty_fields_shows_error - проверка негативных кейсов для метода - попытка создания с
   пропущенными обязательными полями.


2. **Проверка API метода "Логин курьера в системе" (test_login_courier.py):**  
   test_login_courier_success - успешная авторизация курьера в системе;  
   test_login_courier_empty_fields_show_error - ошибка при авторизации с пустым логином или паролем;  
   test_login_courier_incorrect_fields_show_error - ошибка при использовании неверного логина или пароля;  
   test_login_courier_nonexistent_courier_show_error - авторизация несуществующего пользователя;


3. **Проверка API метода "Создание заказа" (test_create_order.py):**  
   test_create_order_success - создание заказа с параметризацией по цветам самоката.


4. **Проверка API метода "Получение списка заказов" (test_get_orders_list.py):**  
   test_get_orders_list_success - успешное получения списка заказов.


5. **Проверка API метода "Удаление курьера" (test_delete_courier.py):**  
   test_delete_courier_success - успешное удаления курьера по id;  
   test_delete_courier_nonexistent_id_shows_error - ошибка при попытке удаления курьера с несуществующим id;  
   test_delete_courier_without_id_shows_error - ошибка при попытке удаления без передачи id.


6. **Проверка API метода "Принять заказ" (test_accept_order.py):**  
   test_accept_order_success - успешное принятие заказа;  
   test_accept_order_order_validation - негативные проверки: передача невалидного id/пустого id заказа.  
   test_accept_order_courier_validation - негативные проверки: передача невалидного courier_id/пустого courier_id.  


7. **Проверка API метода "Получить заказ по его номеру" (test_get_order_by_track.py):**  
   test_get_order_by_track_success - успешный поиск заказа по корректному номеру трека;   
   test_get_order_by_track_empty_number_shows_error - ошибка при попытке получить заказ по пустому номеру; </br>
   test_get_order_by_track_invalid_number_shows_error - ошибка при попытке получить заказ по невалидному номеру. </br>

### Запуск тестов

1. Установите зависимости:  
   pip install -r requirements.txt
2. Запустите тесты:  
   pytest tests

### Генерация отчета Allure

1. Запустите тесты с генерацией данных для отчета:  
   pytest --alluredir=allure-results
2. Сгенерируйте отчет и откройте его в браузере:
   allure serve allure-results

### Список найденных багов

**BUG-1: несоответствие ответа при создании курьера с существующим логином**  
**Шаги:** отправить запрос POST /api/v1/courier c логином курьера, который уже есть в базе.  
**Ожидаемый результат:** тело ответа: {"message": "Этот логин уже используется"}.  
**Фактический результат:** тело ответа: {"code": 409, "message": "Этот логин уже используется. Попробуйте другой."}

**BUG-2: лишнее поле "code" в ответе метода "Создание курьера" при создании курьера без логина или пароля**  
**Шаги:** отправить запрос POST /api/v1/courier c пустым логином или паролем.  
**Ожидаемый результат:** тело ответа: {"message": "Недостаточно данных для создания учетной записи"}.

**Фактический результат:** Статус-код 404. Тело ответа: {"code": 404, "message": "Not Found."}

**BUG-7: [Flaky] Периодическая ошибка 404 при подтверждении заказа**
**Шаги:**

1. Создать курьера - отправить запрос POST /api/v1/courier
2. Создать заказ - отправить запрос POST /api/v1/orders.
3. Сразу вызвать метод PUT /api/v1/orders/accept/:id?courierId=courier_id, где id - трек-номер созданного заказа,
   courier_id - id созданного курьера.
4. Повторить цикл 10 раз.

**Ожидаемый результат:** все 10 запросов возвращают статус-код 200.  
**Фактический результат:** в ~70% случаев (7 из 10) сервер возвращает статус-код 404, хотя заказ был успешно создан
секундой ранее.
